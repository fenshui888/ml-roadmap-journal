## Тема: Чем Docker-образ отличается от контейнера?
<h4>1. Объяснение для 12-летнего (3-6 предложений, без терминов)</h4>
<b><i>Образ</i></b>- это инструкция и набор файлов, необходимых для запуска программы. 
<b><i>Контейнер</i></b>- это отдельный экземпляр программы, созданный на основе образа.
Один и тот же образ можно использовать для запуска множество контейнеров. Сам образ не является запущенной программой. Контейнеп может работать, останавливаться и запускаться снова. 
<u>Образ - основа для создания контейнеров, а контейнер - отдельный экземпляр этой основы.</u>

<h4>2. Аналогия из жизни</h4>
<b><i>Образ = рецепт пиццы.</i></b>
<b><i>Контейнер = процесс приготовления  пиццы по этому рецепту.</i></b>

Можно взять один рецепт и приготовить:
* одну пиццу
* десять пицц
* сто пицц

<u>Рецепт остаётся тем же, а количество готовых пицц может быть разным.</u>

<h4>3. Пример</h4>
<b><i>Образ = docker image ls</i></b> -> <u>В списке может находиться образ python:3.11</u>
Запускаем контейнер: 
<strong>docker run python:3.11</strong> Docker cоздаётся контейнер на основе образа python3:11 и запускает в нём Python.
Однако команда запускает Python без интерактивного терминала. Когда стандартный ввод закрывается, интерпретатор получает конец входных данных и завершает работу. Контейнер тоже останавливается.
Проверяем работающие контейнеры:
Проверяем: <b><i>docker ps</i></b> -> <u>CONTAINER ID: 8f7g3m...</u>

* python:3.11 -> Образ
* 8f7g3m... -> Контейнер

<u>Можно запустить ещё несколько контейнеров из этого образа.</u>
<strong>docker ps -a</strong>
Здесь можно увидеть созданный контейнер со статусом Exited.
<p>Запускаем Python в интерактивном режиме:</p>
<strong>docker run -it --name python-demo python3:11</strong>
Теперь Python работает в интерактивном терминале. Пока интерпретатор запущен, в другом терминале можно выполнить:
<strong>docker ps</strong>
Контейнер python-demo будет отображаться среди работающих контейнеров.
После завершения работы контейнер перестанет отображаться в docker ps, но останется доступен в docker ps -a.
Памятка:

* python:3.11 — образ;
* python-demo — имя контейнера;
* docker ps — показывает работающие контейнеры;
* docker ps -a — показывает все контейнеры, включая остановленные;
* docker run — создаёт и запускает контейнер;
* -it — позволяет взаимодействовать с программой через терминал.
Важно: создание контейнера не означает, что он будет работать постоянно. Контейнер может завершиться сразу после выполнения своей основной команды.
<h4>4. Где я застрял/в чём не уверен</h4>
Образ и контейнер - это одно и то же.
Правильное понимание:

* Образ (image) — шаблон, на основе которого создаются контейнеры.
* Контейнер (container) — отдельный экземпляр, созданный на основе образа.
* Работающий контейнер выполняет свою основную команду.
* Остановленный контейнер не удаляется автоматически: его можно увидеть через docker ps -a.
Главный вывод: один образ может использоваться для создания множества контейнеров, а каждый контейнер имеет собственное состояние и может работать независимо от других.
